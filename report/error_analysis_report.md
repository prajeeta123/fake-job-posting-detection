## Pattern observations

False-positive text most often included these terms/phrases: service, ability, customer, data, office, customer service, time, strong. These overlaps are descriptive, not proof of why the classifier made each decision. False negatives were frequently missing company profiles (31/36) and salary information (22/36); 9 lacked requirements and 7 had descriptions under 250 characters.

## Three practical feature-engineering improvements

1. Add section-aware text indicators for suspicious claims or requests, scored separately in the description, requirements, and company profile (for example payment/fee requests and messaging-only contact cues). Validate phrase patterns on training-only validation data.
2. Add robust compensation features: salary present/missing, parseable lower/upper bounds, currency, hourly-versus-annual clues, and outlier or unusually broad range flags; treat unparsable values as unknown rather than assuming fraud.
3. Add structured completeness and consistency signals, such as company-profile and requirements missingness, description length, and agreement between remote-work wording and telecommuting metadata. Evaluate all signals without using the held-out test set for selection.

Any feature experiments should be compared using training-only validation. Do not select features, change thresholds, or tune on the held-out test results in this report.
