# 7. System Architecture

## 7.1 Training and analysis workflow

```text
Raw DataSet.csv
       |
       v
Schema/label inspection and exact-row deduplication
       |
       v
Deterministic text cleanup + engineered counts/indicators
       |
       v
Stratified train/test split (80/20, random_state=42)
       |
       +--> Training-only inner validation --> candidate comparison/model selection
       |                                          |
       |                                          v
       |                                  Saved hybrid pipeline
       |                                          |
       |                                          v
       |                               Training-only calibration
       |
       +--> Training-only threshold validation --> model_threshold.json
       |
       +--> Held-out test --> final evaluation and SHAP explanations
```

## 7.2 Application inference workflow

```text
User-entered posting text and metadata
       |
       v
Same text combination/cleanup and deterministic feature generation
       |
       v
models/fake_job_detector.joblib
  (fitted text/category/numeric preprocessing + calibrated classifier)
       |
       v
Fraud probability --> compare with models/model_threshold.json
       |
       v
Label, risk display, indicator warnings, safety recommendations
```

## 7.3 Components and boundaries

- `notebooks/`: data inspection, feature construction, model experiments, verification, threshold analysis, and explainability.
- `src/fit_app_calibrator.py`: creates a probability-calibrated copy of the selected pipeline using training data only.
- `models/fake_job_detector.joblib`: serialized complete calibrated preprocessing and classifier pipeline.
- `models/model_threshold.json`: validation-selected F1 threshold and a documented high-recall alternative.
- `app.py`: local Streamlit interface and input feature generation.
- `report/`: generated experiment outputs and the academic project report.

The application does not send posting content to a third-party API or cloud AI service. Model artifacts should be generated by the project workflow and kept compatible with the input schema used by the app.
